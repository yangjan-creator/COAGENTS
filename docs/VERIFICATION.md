The concurrent-gate test holds a PostgreSQL row lock until both handlers are waiting, then
releases them. This exercises the stale-read boundary, rather than relying on two requests
accidentally running sequentially. Gate/version state is refreshed after the item lock.
Dependency graph edits serialize per project so disjoint edges cannot jointly form a cycle.

The Dashboard browser test is opt-in and creates labeled synthetic DEMO records. It requires
Playwright 1.58.0 and its Chromium installation. See [Quickstart](QUICKSTART.md).
To repeat the PostgreSQL gate test after seeding DEMO, run:

```bash
docker cp scripts/postgres_smoke.py coagents-api-1:/tmp/coagents_postgres_smoke.py
docker compose exec -T api python /tmp/coagents_postgres_smoke.py
docker compose exec -T api python -c 'from pathlib import Path; Path("/tmp/coagents_postgres_smoke.py").unlink()'
```

It creates one synthetic work item/version/gate and revokes its temporary reviewer key.
It makes no database copies. The project data and audit event are retained as synthetic evidence.
The service's private `.env` is ignored by Git and excluded from the Docker context.

Not tested or not implemented: multi-host deployment, SSO, scheduling, arbitrary future
SQL schema migrations, external file/process verification, and automatic Git/deploy execution.
No external PM product is contacted. No provider LLM calls are made by these checks.

## Review contract for later increments / 後續增量驗證

This is review guidance, not a claim that every check below is automated in the current
service. The smoke record above does not attest later SQL or UI candidates. Each later
WorkVersion needs its own declared gates and evidence; `PLAN VERIFIED` does not open DEV,
and isolated DEV verification does not authorize deployment.

| Evidence requirement | What to preserve | What is not sufficient |
|---|---|---|
| Exact subject / 對象 | WorkVersion, fixed source URI and SHA for the same body, base revision, environment and final consumer | A current line number, filename, or another version's green result |
| Discriminating gate / 可辨別的尺 | A clean positive control and a real mutation with the observed failure field/code | Empty expected sets, or expected and actual generated by the same unchecked transformation |
| Versioned migration / 真版本升級 | Start from the previously released, versioned schema and ledger; upgrade it with the candidate; check retained rows and history | Bootstrapping an empty database, or adopting an unversioned fixture only |
| Constraint semantics / 約束語意 | Clean reflected constraints plus changed-precedence and actual insert/update counterexamples | Removing all parentheses or other meaningful syntax from both sides of a comparison |
| Source field fidelity / 原欄保真 | Endpoint and operation, raw field name/type, absence versus null, raw versus normalized display value | A request parameter treated as a response schema, or candidate field names presented as provider fields |
| Delivery and effects / 交付與副作用 | Receipt, final consumer readback, owner and cleanup evidence; state exactly what was not run | Author ACK, a saved document, healthy endpoint, or an internal producer alone |

Migration fingerprints must be revision-scoped: a newly added revision must not make an
unchanged, previously released ledger invalid. Do not rewrite historical ledger hashes to
make a comparison pass. Also retain a tampered-history negative control so compatibility
does not become a blanket exemption for old databases.

For CHECK comparisons, normalize only proven formatting differences. Preserve boolean
grouping and string contents. An unsupported expression must remain distinguishable or be
reported as unsupported; it must not silently become equal to a different expression.

Record test denominators and skips. For example, SQLite passes with PostgreSQL skips are
SQLite evidence, not independent PostgreSQL verification. A developer's PostgreSQL run may
be useful evidence, but it must not be relabelled as the reviewer's own run.

Corrections append new evidence and cite the original decision. Keep old FAILED versions;
repair through a successor WorkVersion. The reviewer declares all required gates before
recording terminal results. No declared gates means `NOT_DECLARED`, not a pass.

Use synthetic, owner-labelled fixtures. Database files are not report attachments: keep
large scratch data outside the repository, inspect processes/mounts and retention needs,
then delete disposable copies after their results are retained. Never delete a sole input
or rollback point merely because a test ended. The file registry records metadata and
attestations; it does not prove process safety or physically delete files.
